# 第3回 解答

## 演習

- 第1回（素のLLM）とエージェントの回答の違い：
  - 質問：「AIE2026の講座の宿題にある「3レベル」とは何ですか？」
  - 素のLLM（`app.ask`）は講座の定義を知らないため、一般的な「レベル1〜3」の説明を推測で答え、公式の説明を確認するよう補足した
  - エージェントは用語集を検索し、「基礎・実装・発展のどれか1つに取り組めば完了」と講座の定義どおりに答えた
- `--trace` で見えたツール呼び出し（ツール名と引数）：
  - 3レベルの質問：`search_glossary({'query': '3レベル'})`
  - 「LoRAとQLoRAの違いは？」：`search_glossary({'query': 'LoRA'})`、`search_glossary({'query': 'QLoRA'})`
  - 確認問題：`make_quiz({'lecture': 2})`
- 1つの質問での LLM 呼び出し回数（`requests`）：
  - 3つの質問すべてで `requests=2`（ツールを決める → 結果を読んで回答する）
  - LoRA の質問はツールを2回呼んだが、1回の応答で2つ同時に呼んだため `requests=2`、`tool_calls=2` だった
- 追加したツールと、docstring に書いた説明：
  - `make_quiz(lecture: int)`：指定した回の用語を1つ選び、問題と答えを JSON で返す。用語がない回は、問題を作れる回を案内する
  - docstring：「指定した回（1始まりの整数）の用語から確認問題を1問作り、問題と答えを返す。「第2回の確認問題を出して」のように、復習用の問題を求められたときに使う。」

## 宿題

- 取り組んだレベル：基礎
- やったこと：
  - `search_glossary` の docstring だけを変更して比べた
  - 変更前：「query には調べたい用語を1つだけ入れる（例: "LoRA"）。」
  - 変更後：「query には調べたい用語をまとめて入れる（例: "LoRA QLoRA"）。」
  - 同じ質問「LoRAとQLoRAの違いは？」を、同じモデル（`gemini-3.5-flash-lite`）で各3回実行した
- 結果：

  | | 変更前（1つだけ） | 変更後（まとめて） |
  |---|---|---|
  | ツール呼び出し | `LoRA` と `QLoRA` に分けて2回（3回とも） | `LoRA QLoRA` で1回（3回とも） |
  | `requests` | 2 | 2 |
  | `tool_calls` | 2 | 1 |
  | 入力トークン | 1360 | 1055 |
  | 出力トークン | 195 / 176 / 179 | 197 / 229 / 215 |
  | 検索で返った用語 | `LoRA`、`ランク（LoRAのr）`、`QLoRA` と、`QLoRA`、`LoRA` | `LoRA`、`QLoRA` |
  | 回答 | LoRA と QLoRA の違いを説明 | 同じく違いを説明 |

- 気づき・疑問：
  - docstring を1文変えるだけで、モデルが作る引数と呼び出し回数が3回とも変わった。ツールの説明文はモデルへの指示として働く
  - 今回は「まとめて」のほうが重複した検索結果が減り、入力トークンも少なかった
  - ただし、これは `search_glossary` が「LoRA QLoRA」のような連結語でも両方を見つけられたためで、用語の組み合わせによっては見つからない可能性がある。説明文はツールの実装に合わせて書く必要がある
